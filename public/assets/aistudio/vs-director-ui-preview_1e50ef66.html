Full Change Log

All 18 sections of the CSS patch, with scope tags.

🏷️
Shared Design Tokens

Added --cg-* CSS variables for gap, radius, accent, and surface colors. These cascade through both Classic and Studio surfaces without touching existing tokens.

Both UIsCSS vars
📐
Classic Header — No-wrap & spacing

Forces flex-wrap: nowrap on ≥1280px so the toolbar never breaks into 3 rows. Responsive override at <820px lets it wrap gracefully. Brand PRO badge gets a proper border.

Classic
⚡
Visual-First & Upload Audio — Stronger CTAs

Visual-First gets a gradient background + glow box-shadow on hover. Upload Audio gets an amber glow. Both have active-state scale transforms. These are the two most-clicked buttons in the modal — they needed to look like primary actions.

Classic
🔴
Export & Close — Clear intent

Export button scales up on hover with a stronger indigo glow. Close button gets a rose tint on hover so it reads as a destructive action, not just a generic button.

Classic
📹
Video Progress Bar — Responsive height + glow

Bar thickens on hover (3px → 6px) with a smooth transition. The fill gradient gains a box-shadow so the playhead position is visible on dark frames.

Classic
🎞️
Timeline Clips — Gradients & selected state

Each clip type (video, audio, overlay, music) now uses a subtle directional gradient instead of flat opacity. Selected clips get a white border + indigo glow ring so they're unmissable.

Both UIs
▼
AI Director Dropdown — Colored icon badges

Each item in the dropdown gets a colored icon badge (amber = pattern interrupt, purple = magic polish, teal = overlays) matching the semantic meaning. Dropdown panel gets a rounder border-radius (16px) and a stronger shadow.

Classic
🏢
Studio Topbar — Brand glow, cleaner group spacing

Brand icon gets a drop-shadow glow. Back-to-Storyboard button gains an indigo hover. Exit Classic gets an amber tint. Close gets rose-danger hover.

Studio
🗂️
Panel Resizers — Wider hit area + accent drag

Resizer dividers are 6px wide (up from ~2px) for easier grabbing. The ::after pseudo-element turns indigo on hover.

Studio
📂
Left Asset Panel Tabs — Gradient active state

Active tab gets the same linear-gradient(indigo → indigo-dim) treatment as the inspector tabs for visual consistency.

Studio
🔍
Right Inspector Tabs — Gradient + border glow

Active inspector tab uses the same gradient + border treatment. Inactive tabs get a subtle hover state that was previously absent.

Studio
🗃️
Production Cards — Uniform radius + hover border

All .vs-prod-card elements get border-radius 9px, a darker header background, and a hover border-color so they feel interactive.

✂️
Transitions Panel — Hover translate + selection glow

Transition cards lift 2px on hover. Active card gains a double-ring shadow (1px solid + diffuse glow). Category pills get the standard indigo gradient when active.

🎚️
Inspector Sliders & Inputs — Focus rings

All range thumbs get an indigo border + glow. All text inputs get a 2px indigo focus ring that replaces the default blue browser outline.

Export selects, inputs, and radio-style format buttons all share the same dark input theme with focus and active states.

Install Guide

Three ways to apply the patch — pick whichever matches your build setup.

1
Option A — Add to index.html Easiest
Drop one line after your existing CSS link.
<!-- After your existing stylesheet -->
<link rel="stylesheet" href="src/styles/vs-director.css">
<link rel="stylesheet" href="vs-director-improvements.css"> <!-- ← add this -->
2
Option B — Vite / bundler import
Import in your entry point so it tree-shakes and bundles correctly.
// In src/main.ts or src/index.ts — AFTER the existing import
import './styles/vs-director.css'
import '../../vs-director-improvements.css' // ← add this
3
Option C — Append to vs-director.css Cleanest for prod
Merge the patch into the main stylesheet with one command.
# From your project root
cat vs-director-improvements.css >> src/styles/vs-director.css
⚠️
Zero DOM changes required
All selectors target existing IDs and class names from your codebase. If you rename any element IDs in a future refactor, update the matching selector in the patch file. The patch uses !important sparingly (only where Tailwind inline styles override declarations) — prefer specificity upgrades if you later restructure.
